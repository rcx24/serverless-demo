# `finance-exports`

The bucket the attacker enumerates and reads from, and twelve months of synthetic exports
inside it.

## Everything here is chosen to survive being read on screen

**The bucket name has no "demo" in it.** An analyst reads this name aloud while
reconstructing what was taken. `serverless-demo-exports` would tell the room they are
looking at a fixture, and a test fails if the name ever picks up `demo`, `test`, `example`
or `serverless`.

The account id is appended by default, because S3 bucket names are globally unique and
`acme-finance-exports` is almost certainly taken. A `BucketAlreadyExists` two modules into
an apply is a bad way to discover that. Set `unique_suffix = false` if you have secured
the bare name.

**The object keys are dated and hierarchical** — `exports/2026/07/cost-allocation-2026-07.csv`.
That is what makes *"they took July and August"* a sentence somebody says out loud rather
than a lookup they perform.

**There are twelve objects and the attacker reads two or three.** A bucket holding only
the objects that get read would remove the analyst's job of working out which ones
mattered.

**The contents are invented.** Made-up vendor names, round-ish numbers, nothing resembling
a real person or a real company's finances. Note that the read-only role cannot read these
objects at all, so nobody in the room ever sees the contents — but anyone with account
access can, and this is an account that gets screen-shared.

## `force_destroy = true`, unlike quiv-iac's object store

Deliberately opposite to the convention in the sibling repo, and for a reason specific to
this one: `serverless-demo teardown` has to return the account to baseline **unattended**,
including in CI. Everything in this bucket is regenerated by the next apply, so there is
nothing here worth the manual step that `force_destroy = false` would impose.

That setting must not be copied to anything holding data that is not reproducible.

## Why the bucket policy exists at all

The bucket is not public and never should be. The `DenyInsecureTransport` policy is there
because the demo puts this bucket's policy on screen during blast-radius analysis, and an
empty policy invites the question of what else is missing. It carries the control an
auditor would expect to find.
